# Проектирование ИТ-решений: System Design и архитектура данных

Курс для студентов бизнес-информатики по проектированию верхнеуровневой архитектуры ИТ-систем с усиленным модулем по моделированию данных, выбору СУБД и стратегиям масштабирования.

## 1. Цель курса

Сформировать у студентов инженерное мышление и практические компетенции в области System Design, научить переводить бизнес-цели в архитектурные решения и подготовить фундамент (в виде итогового Architecture Blueprint) для углублённого изучения курса "Базы данных" в следующем семестре.

**Ключевой принцип:** 80% успеха ИТ-продукта закладывается на этапе проектирования. Программирование — тактика, System Design — стратегия.

Студенты научатся:
- Переводить бизнес-цели в архитектурные драйверы и метрики успеха (SLO/SLA)
- Анализировать предметную область через Event Storming и диаграмму Исикавы
- Проектировать концептуальные и логические модели данных (3НФ), планировать миграции схемы
- Выбирать класс СУБД на основе теорем CAP/PACELC и требований к транзакциям (ACID)
- Проектировать стратегии Data Governance (PII, GDPR, 152-ФЗ) и безопасности
- Обеспечивать надёжность данных (репликация, RPO/RTO) и масштабирование (кэширование, OLTP vs OLAP)
- Фиксировать архитектурные компромиссы в ADR (Architecture Decision Records)
- Проводить взаимное рецензирование (Peer-Review) и защищать проект

## 2. Аудитория

- Студенты направлений "Бизнес-информатика" и "Программная инженерия"
- ИТ-менеджеры, Product Owners, CIO
- Начинающие Solution Architects и System Analysts
- Слушатели, готовящиеся к техническому курсу "Базы данных" (следующий семестр)

**Требования:** базовое понимание информационных систем, бизнес-процессов и основ программирования. Глубокие знания SQL или администрирования СУБД **не требуются**.

## 3. Формат

- **Количество лекций:** 8
- **Продолжительность:** 80 минут каждая + сквозной проект
- **Формат проведения:** Лекции (с интерактивом Mentimeter/Slido) + практические занятия + кейсы + Peer-Review
- **Итоговая работа:** Architecture Blueprint (служит ТЗ для следующего семестра)

### Структура курса (обновлённый план):
1. **Введение в System Design и проектирование ИТ-решений** — бизнес-цели, архитектурные драйверы, C4 Model, ADR
2. **Предметная область, Event Storming и диаграмма Исикавы** — Bounded Contexts, анализ процессов, требования (BABOK, SMART, MoSCoW)
3. **Модели данных, нормализация и эволюция схемы** — концептуальная/логическая модели, 3НФ, Zero-Downtime миграции
4. **История и виды СУБД, транзакции, PACELC, Data Governance** — выбор СУБД, ACID, уровни изоляции, защита PII
5. **Взаимодействие с СУБД, уязвимости и инструменты разработчика** — пулы соединений, ORM/N+1, SQL-инъекции, DBeaver/DataGrip
6. **Надёжность данных: репликация, бэкапы, восстановление** — синхронная/асинхронная репликация, PITR, RPO/RTO
7. **Финальная сборка, Peer-Review и защита отчёта** — System Design компоненты, CQRS/Event Sourcing, взаимное рецензирование
8. **Масштабирование: кэширование, индексирование, OLTP vs OLAP** — паттерны кэширования, B-Tree, Data Warehouse, ETL/ELT

### Оценивание:
- Итоговый отчёт (Architecture Blueprint): **50%**
- Peer-Review (взаимное рецензирование): **10%**
- Защита проекта (презентация + Q&A): **20%**
- Практические задания: **20%**

## 5. Как использовать репозиторий с AI-агентом

Этот репозиторий предназначен для генерации учебного курса с помощью AI-агента. Курс готовит **архитектурный фундамент (WHAT и WHY)**, который станет Техническим Заданием (ТЗ) для практической реализации (HOW) в следующем семестре на курсе "Базы данных".

### Порядок работы:

1. **Изучите спецификации** (`specs/`) — AI должен понимать цели курса, структуру 8 лекций и связь со следующим семестром
2. **Проверьте базу знаний** (`knowledge/`) — источник фактической информации (теории, паттерны, источники)
3. **Используйте шаблоны** (`templates/`) — единый формат материалов (лекции, практики, ADR, Peer-Review)
4. **Генерируйте контент** в `content/lectures/` согласно контрактам из `specs/content-contracts/`
5. **Соблюдайте академическую честность** — все цитаты оформляйте в APA/MLA, избегайте плагиата
6. **Ведите бэклог** в `tasks/backlog.md` — отслеживайте прогресс подготовки лекций

### Рекомендуемый порядок генерации:

```
1. Обновить specs/ (syllabus, module-map, learning-outcomes, course-charter)
2. Создать/обновить knowledge/ (база знаний по всем темам)
3. Обновить templates/ (добавить peer-review.md, architecture-brief.md)
4. Создать specs/lessons/lesson-01.spec.md ... lesson-08.spec.md
5. Генерация Лекции 1 (Введение в System Design)
6. Генерация Лекции 2 (использует кейс из Лекции 1)
7. Генерация Лекции 3 (использует домен из Лекции 2)
8. Генерация Лекции 4 (использует модель данных из Лекции 3)
9. Генерация Лекции 5 (использует выбор СУБД из Лекции 4)
10. Генерация Лекции 6 (использует СУБД из Лекции 5)
11. Генерация Лекции 7 (интегрирует Лекции 1-6, Peer-Review)
12. Генерация Лекции 8 (масштабирование, OLAP, ETL)
```

### Примеры команд для AI-агента:

- "Сгенерируй Лекцию 1 по теме 'Введение в System Design', используя шаблон `templates/lesson.md` и базу знаний из `knowledge/system-design/`"
- "Создай практику к Лекции 3 (нормализация), следуя `templates/practice.md` и `specs/practice-contract.md`"
- "Проверь сгенерированную Лекцию 4 на соответствие `specs/content-contracts/lesson-contract.md` и академической честности"
- "Обнови глоссарий `knowledge/glossary.md` новыми терминами из Лекции 6 (RPO, RTO, PITR)"

Подробные инструкции для AI-агента см. в файле `AGENTS.md`.

## 6. Правила генерации контента

### Общие принципы:

- **Соответствие спецификациям:** Весь контент должен соответствовать `specs/syllabus.md` и `specs/learning-outcomes.md`
- **Единый стиль:** Использовать шаблоны из `templates/`
- **Проверка фактов:** Сверяться с `knowledge/` для точности информации
- **Постепенность:** От бизнес-целей → к домену → к модели данных → к выбору СУБД → к масштабированию
- **Академическая честность:** Все цитаты оформлять в APA/MLA;禁止 плагиат и «Resume-Driven Development»
- **Связь со следующим семестром:** чётко разделять архитектурный уровень (текущий курс) и технический (следующий курс)

### Требования к материалам:

#### Лекции:
- Соответствуют `specs/content-contracts/lesson-contract.md`
- Длительность материала: ~80 минут
- Содержат: Hook, теорию, Case Study, управленческие выводы, практику, мостик к следующей лекции
- Ссылки на соответствующие разделы `knowledge/`
- Цитаты в формате APA/MLA

#### Практики:
- Соответствуют `specs/practice-contract.md`
- Связаны с кейсом лекции и итоговым Architecture Blueprint
- Содержают: цель, входные данные, задание, шаблон результата, критерии оценки, типичные ошибки
- Выполнимы без программирования (на уровне проектирования)

#### ADR (Architecture Decision Records):
- Формат Найгарда: Title, Status, Context, Decision, Consequences
- Одно решение = один ADR
- Честные последствия (не только плюсы, но и риски)

#### Peer-Review:
- Рубрика из 10 критериев (логика, обоснованность, нормализация, NFR, ADR, академичность)
- Конструктивный фидбэк: критиковать работу, не автора

### Запрещено:
- Выдумывать факты, источники, точные цифры (использовать «примерно» или сверяться с `knowledge/no-hallucination.md`)
- Утверждать, что одна технология подходит для всех задач
- Использовать очередь как полноценную замену БД
- Писать сложный production-код как основной материал лекции
- Генерировать ADR без анализа контекста и последствий
- Использовать AI для написания финального текста без анализа студента

### Контроль качества:
- Использовать `templates/review-checklist.md` для самопроверки каждого материала
- Вести список изменений и статусы в `tasks/backlog.md`
- Все материалы должны быть готовы к Peer-Review
