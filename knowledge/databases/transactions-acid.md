# Транзакции и свойства ACID

## Определение транзакции

Транзакция — логическая единица работы с базой данных, включающая одну или несколько операций, которые выполняются как единое целое: либо все операции успешны, либо все откатываются.

## Примеры транзакций

- **Перевод денег:** списать с аккаунта A → зачислить на аккаунт B
- **Оформление заказа:** создать заказ → зарезервировать товар → создать платёж
- **Регистрация пользователя:** создать аккаунт → создать профиль → отправить приветственное письмо (внешний эффект)

## Свойства ACID

### A — Atomicity (Атомарность)
Все операции транзакции выполняются или ни одна не выполняется.
Механизм: COMMIT (подтверждение) или ROLLBACK (откат).
Если любая операция завершается ошибкой — вся транзакция откатывается.

### C — Consistency (Консистентность)
Транзакция переводит базу данных из одного консистентного состояния в другое.
Все ограничения (PK, FK, UNIQUE, CHECK) соблюдаются.
Пример: после перевода денег сумма на обоих аккаунтах не изменилась.

### I — Isolation (Изоляция)
Параллельно выполняемые транзакции не влияют друг на друга.
Каждая транзакция «видит» данные так, как будто она единственная.
Механизм: блокировки, MVCC (Multi-Version Concurrency Control).

### D — Durability (Долговечность)
После успешного завершения (COMMIT) данные сохранены надёжно, даже при сбое питания.
Механизм: WAL (Write-Ahead Log), fsync.

## Commit и Rollback

### COMMIT
- Подтверждает все изменения транзакции
- Изменения становятся видимыми для других транзакций
- Изменения записываются в WAL и на диск

### ROLLBACK
- Отменяет все изменения транзакции
- База данных возвращается к состоянию до начала транзакции
- Другие транзакции не видят отменённые изменения

### Состояния транзакции
Active → Partially Committed → Committed
Active → Failed → Aborted

## Конкурентный доступ

### Конфликты

| Аномалия | Описание | Уровень изоляции, где допускается |
|:---|:---|:---|
| Lost Update | Две транзакции читают одни данные, обе изменяют, одна перезаписывает другую | Все, кроме Serializable |
| Dirty Read | Чтение данных незакоммиченной транзакции | Read Uncommitted |
| Non-repeatable Read | Повторное чтение даёт разные результаты (данные изменены другой транзакцией) | Read Uncommitted, Read Committed |
| Phantom Read | Появление новых строк при повторном запросе диапазона | Все, кроме Serializable |

### Блокировки

| Тип | Обозначение | Назначение |
|:---|:---|:---|
| Разделяемая (Shared Lock) | S | Чтение. Несколько транзакций могут держать одновременно |
| Исключительная (Exclusive Lock) | X | Запись. Только одна транзакция |

### Deadlock (Взаимная блокировка)

Две транзакции ждут друг друга:
- Транзакция 1 блокирует строку A, ждёт строку B
- Транзакция 2 блокирует строку B, ждёт строку A

**Решение:** СУБД обнаруживает deadlock и откатывает одну из транзакций.

## Уровни изоляции (стандарт SQL)

| Уровень | Dirty Read | Non-repeatable Read | Phantom Read | Производительность |
|:---|:---|:---|:---|:---|
| Read Uncommitted | Допускает | Допускает | Допускает | Максимальная |
| Read Committed | Нет | Допускает | Допускает | Высокая |
| Repeatable Read | Нет | Нет | Допускает | Средняя |
| Serializable | Нет | Нет | Нет | Минимальная |

**Значения по умолчанию:**
- PostgreSQL: Read Committed
- MySQL (InnoDB): Repeatable Read
- Oracle: Read Committed

**Компромисс:** чем выше изоляция, тем ниже производительность и конкурентность.

## Целостность данных

| Тип | Механизм | Пример |
|:---|:---|:---|
| Доменная | Типы данных, CHECK | `price > 0` |
| Сущностная | PK, UNIQUE | `client_id PRIMARY KEY` |
| Ссылочная | FK | `order.client_id REFERENCES client(id)` |
| Пользовательская | Триггеры, процедуры | «Нельзя удалить клиента с заказами» |
