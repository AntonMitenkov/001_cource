# Data Governance и защита данных (PII)

## Определение

Data Governance — совокупность процессов, политик, стандартов и ролей для управления данными в организации. Включает обеспечение качества, безопасности, соответствия регуляторам и управления жизненным циклом данных.

## Персональные данные (PII)

**PII (Personally Identifiable Information)** — данные, позволяющие идентифицировать конкретного человека.

| Категория | Примеры |
|:---|:---|
| Прямые идентификаторы | ФИО, паспорт, ИНН, СНИЛС |
| Контакты | Email, телефон, адрес |
| Биометрия | Отпечатки пальцев, фото лица, голос |
| Онлайн-идентификаторы | IP-адрес, cookie ID, device ID |
| Финансовые | Номер карты, банковский счёт |
| Медицинские | Диагнозы, история болезней |

## Регуляторика

### GDPR (General Data Protection Regulation, ЕС, 2018)

**Ключевые требования:**
- Право на доступ к своим данным
- Право на исправление
- Право на удаление («право на забвение»)
- Право на переносимость данных
- Уведомление о утечках в течение 72 часов
- Штрафы: до 4% годового мирового оборота или 20 млн евро

### 152-ФЗ «О персональных данных» (Россия, 2006)

**Ключевые требования:**
- Согласие субъекта на обработку
- Локализация данных граждан РФ на территории РФ
- Уведомление Роскомнадзора об обработке
- Обеспечение безопасности (шифрование, контроль доступа)
- Право на отзыв согласия

### Другие регуляторы
- **HIPAA** (США) — медицинские данные
- **PCI DSS** — данные платёжных карт
- **SOC 2** — безопасность и доступность

## Паттерны защиты данных

### 1. Маскирование (Masking)
Замена части данных на символы-заполнители.
Пример: `i***@gmail.com`, `+7 (9**) ***-**-45`, `**** **** **** 1234`.

### 2. Токенизация (Tokenization)
Замена чувствительных данных на токен. Оригинальные данные хранятся в защищённом хранилище (например, Vault).
Пример: номер карты → `tok_abc123`; маппинг в Vault.

### 3. Шифрование (Encryption)

| Уровень | Описание | Пример |
|:---|:---|:---|
| At Rest | Шифрование данных на диске | TDE (Transparent Data Encryption), LUKS |
| In Transit | Шифрование при передаче | TLS 1.2/1.3, HTTPS |
| Application-level | Шифрование в приложении | AES-256, библиотеки шифрования |
| Database-level | Шифрование средствами СУБД | pgcrypto (PostgreSQL), MongoDB Client-Side Field Level Encryption |

### 4. Crypto-shredding (Крипто-шреддинг)

**Проблема:** как удалить данные, которые распределены по множеству таблиц, бэкапов, реплик?

**Решение:**
1. Каждый пользователь получает персональный ключ шифрования
2. Все PII пользователя шифруются его персональным ключом
3. Ключ хранится в KMS (Key Management Service)
4. При запросе на удаление: удаляется ключ из KMS
5. Данные остаются физически, но становятся нечитаемыми

**Преимущества:**
- Мгновенное «удаление» без физического удаления данных
- Работает с бэкапами и репликами
- Соответствует «праву на забвение» (GDPR)
