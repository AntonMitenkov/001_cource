# История и эволюция СУБД

## Эра файловых систем (1950-е — 1960-е)

**Хранение:** плоские файлы (текстовые, бинарные).
**Проблемы:**
- Дублирование данных в разных файлах
- Отсутствие целостности (нет связей между файлами)
- Сложность поиска и обновления
- Зависимость от формата файла
- Нет многопользовательского доступа

**Потребность:** централизованное управление данными, целостность, безопасность, конкурентный доступ.

## Ранние модели БД (1960-е)

### Иерархическая модель
- Структура: дерево (родитель → потомки)
- Пример: IBM IMS (Information Management System), 1968
- Плюсы: быстрый доступ по известному пути
- Минусы: сложность представления связей M:N, жёсткая структура

### Сетевая модель
- Структура: граф (многие-ко-многим)
- Стандарт: CODASYL (Conference on Data Systems Languages)
- Плюсы: гибче иерархической
- Минусы: сложность навигации, программирование на низком уровне

## Реляционная модель (1970)

**Автор:** Эдгар Кодд (E.F. Codd), IBM.
**Статья:** "A Relational Model of Data for Large Shared Data Banks" (1970).

**Ключевые идеи:**
- Данные хранятся в таблицах (отношениях)
- Связи выражаются через значения (внешние ключи)
- Доступ через декларативный язык (позже — SQL)
- Математическая основа: теория множеств, предикаты

**Преимущества:**
- Простота понимания
- Гибкость (схема может меняться)
- Математическая строгость
- Целостность через ограничения

## Коммерческие СУБД (1980-е — 1990-е)

- Oracle (1979)
- IBM DB2 (1983)
- Microsoft SQL Server (1989)
- Sybase (1984)

SQL становится стандартом (ANSI SQL-86, SQL-92).

## Открытые СУБД (1990-е — 2000-е)

- MySQL (1995) — простота, скорость для web
- PostgreSQL (1996) — расширяемость, стандарты, академическая строгость
- SQLite (2000) — встраиваемая, для мобильных и десктопных приложений

## Облачные СУБД (2010-е)

- Amazon RDS (2009) — managed PostgreSQL, MySQL, Oracle, SQL Server
- Google Cloud SQL (2011)
- Azure SQL Database (2010)
- Amazon Aurora (2014) — cloud-native, разделение хранения и вычислений

## NoSQL революция (2010-е)

**Причины:**
- Большие данные (Big Data)
- Горизонтальное масштабирование
- Гибкая схема
- Высокая производительность для специфических задач

**Термин:** «NoSQL» = «Not Only SQL» (не только SQL).

**Типы:**
- Документные: MongoDB (2009)
- Ключ-значение: Redis (2009), Memcached
- Колоночные: Cassandra (2008), HBase
- Графовые: Neo4j (2007)

## Векторные СУБД и AI (2020-е)

- Рост AI/ML, LLM, RAG
- Потребность в хранении и поиске эмбеддингов
- Примеры: Pinecone (2021), Qdrant (2022), Weaviate, Milvus
- pgvector — расширение PostgreSQL для векторного поиска
