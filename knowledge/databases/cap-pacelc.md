# CAP-теорема и PACELC

## CAP-теорема (Теорема Брюэра)

**Автор:** Эрик Брюэр (Eric Brewer), 2000 ( conjecture), 2002 (доказательство Гилбертом и Линчем).

**Утверждение:** распределённая система может одновременно гарантировать не более двух из трёх свойств:

| Свойство | Описание |
|:---|:---|
| **C**onsistency (Согласованность) | Все узлы видят одни и те же данные в один момент времени |
| **A**vailability (Доступность) | Каждый запрос получает ответ (успех или ошибка), но не таймаут |
| **P**artition tolerance (Устойчивость к разделению) | Система работает при потере связи между узлами |

### Классификация систем

| Тип | Описание | Примеры |
|:---|:---|:---|
| **CP** | Согласованность + устойчивость к разделению. При разбиении сети жертвуют доступностью. | ZooKeeper, HBase, etcd |
| **AP** | Доступность + устойчивость к разделению. При разбиении сети жертвуют согласованностью. | Cassandra, DynamoDB, CouchDB |
| **CA** | Согласованность + доступность. Не устойчивы к разделению сети. | Традиционные RDBMS (PostgreSQL, MySQL) в single-node |

### Критика CAP

- Partition (разбиение сети) — редкое событие в нормально работающих системах
- Что происходит в **обычное** время (когда сеть работает)?
- Выбор не бинарный: можно настраивать степень консистентности и доступности
- Теорема упрощает реальность

## PACELC

**Автор:** Дэниэл Абади (Daniel Abadi), 2010.
**Цель:** расширить CAP, описав поведение системы в штатном режиме.

**Формула:**
Если есть разбиение сети (P):
выбираем A (доступность) или C (согласованность)
Иначе (E — Else, нормальная работа):
выбираем L (Latency, задержка) или C (консистентность)


### Обозначения

- **PA/EL** — при разбиении: доступность; в норме: низкая задержка (жертвуем консистентностью)
- **PA/EC** — при разбиении: доступность; в норме: консистентность
- **PC/EL** — при разбиении: консистентность; в норме: низкая задержка
- **PC/EC** — при разбиении: консистентность; в норме: консистентность

### Примеры систем по PACELC

| Система | PACELC | Пояснение |
|:---|:---|:---|
| DynamoDB | PA/EL | Всегда доступна, жертвует консистентностью ради скорости |
| Cassandra | PA/EL | Аналогично |
| PostgreSQL (single-node) | PC/EC | Консистентность и в норме, и при сбоях |
| MongoDB | PC/EC (или PA/EL) | Зависит от настроек |
| MySQL (InnoDB) | PC/EC | Консистентность приоритетна |
| Redis (Cluster) | PA/EL | Доступность и скорость |
