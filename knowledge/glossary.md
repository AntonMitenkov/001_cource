# Глоссарий терминов курса

## A
- **ACID** — Atomicity, Consistency, Isolation, Durability. Набор свойств, гарантирующих надёжность транзакций в реляционных СУБД.
- **ADR (Architecture Decision Record)** — документ для фиксации архитектурного решения. Формат: Title, Status, Context, Decision, Consequences. Автор формата: Майкл Найгард.
- **Агрегат (Aggregate)** — в DDD: кластер сущностей и объектов-значений, рассматриваемый как единое целое для целей изменения данных. Граница транзакции.
- **Аномалия данных** — нежелательная ситуация при работе с данными: аномалия вставки, обновления, удаления. Устраняется нормализацией.

## B
- **B-Tree (B-дерево)** — сбалансированная древовидная структура данных, используемая для индексов в СУБД. Обеспечивает поиск за O(log N).
- **Bounded Context (Ограниченный контекст)** — в DDD: явная граница, внутри которой модель предметной области остаётся консистентной. Разные контексты могут иметь разные модели одной бизнес-сущности.
- **БАКОП (Резервное копирование)** — процесс создания копии данных для восстановления в случае потери.

## C
- **C4 Model** — модель визуализации архитектуры из 4 уровней: Context, Container, Component, Code. Автор: Саймон Браун.
- **CAP-теорема** — утверждение Эрика Брюэра (2000): распределённая система может одновременно гарантировать не более двух из трёх свойств: Consistency, Availability, Partition tolerance.
- **Cache-Aside** — паттерн кэширования: приложение проверяет кэш; при промахе читает из БД и записывает в кэш.
- **CHECK (ограничение)** — ограничение в СУБД, задающее условие для значения колонки.
- **Connection Pool (Пул соединений)** — кэш предварительно созданных соединений с БД для снижения накладных расходов.
- **CQRS (Command Query Responsibility Segregation)** — архитектурный паттерн разделения операций чтения и записи.
- **Crypto-shredding** — паттерн удаления данных: шифрование PII персональным ключом; при удалении — удаление ключа из KMS, данные становятся нечитаемыми.

## D
- **Data Governance** — совокупность процессов, политик и стандартов для управления данными в организации. Включает защиту PII, соответствие регуляторам.
- **DDL (Data Definition Language)** — подмножество SQL для определения структуры данных (CREATE, ALTER, DROP).
- **Денормализация** — осознанное введение избыточности в нормализованную схему для повышения производительности чтения. Требует ADR.
- **Dirty Read** — аномалия чтения: транзакция читает данные, изменённые другой незакоммиченной транзакцией.
- **Домен (Domain)** — сфера деятельности, для которой создаётся программное решение (например, E-commerce, FinTech, HealthTech).

## E
- **ETL (Extract, Transform, Load)** — процесс извлечения, трансформации и загрузки данных в хранилище.
- **ELT (Extract, Load, Transform)** — альтернатива ETL: данные загружаются в хранилище, трансформация происходит внутри.
- **Event Sourcing** — паттерн хранения состояния как последовательности событий. Позволяет восстановить любое состояние.
- **Event Storming** — метод совместного анализа бизнес-процессов с использованием стикеров. Изобретён Альберто Брандолини (2013).

## F
- **FK (Foreign Key, Внешний ключ)** — колонка, ссылающаяся на первичный ключ другой таблицы. Обеспечивает ссылочную целостность.
- **Функциональная зависимость** — отношение между атрибутами: X → Y означает, что каждому значению X соответствует единственное значение Y.

## G
- **GDPR (General Data Protection Regulation)** — регламент ЕС по защите персональных данных. Штрафы до 4% годового оборота.

## H
- **Hot Spot** — в Event Storming: проблемная зона, обнаруженная в ходе анализа (розовый стикер).

## I
- **Импеде́нс-мисма́тч (Impedance Mismatch)** — несоответствие между объектной моделью приложения и реляционной моделью БД. Проблема при использовании ORM.

## K
- **Ключ первичный (PK, Primary Key)** — уникальный идентификатор строки в таблице. Не может быть NULL. Один на таблицу.
- **Ключ суррогатный** — искусственно сгенерированный идентификатор (UUID, SERIAL). Не несёт бизнес-смысла, но неизменен.
- **Ключ естественный** — идентификатор, имеющий бизнес-смысл (Email, ИНН). Понятен, но может измениться.
- **Ключ составной** — первичный ключ из нескольких колонок. Часто используется в промежуточных таблицах для связи M:N.

## L
- **Lost Update** — аномалия конкурентного доступа: две транзакции читают одни данные, обе изменяют, одна перезаписывает результат другой.

## M
- **Миграция БД** — версионированное изменение схемы базы данных. Инструменты: Flyway, Liquibase, Alembic.
- **MoSCoW** — метод приоритизации требований: Must, Should, Could, Won't have.

## N
- **N+1 проблема** — проблема ORM: вместо одного запроса с JOIN выполняется 1 запрос для родителя + N запросов для каждого дочернего объекта.
- **Нормализация** — процесс организации данных для устранения избыточности и аномалий. Нормальные формы: 1НФ, 2НФ, 3НФ, БКНФ, 4НФ, 5НФ.
- **НФ (Нормальная форма)** — уровень нормализации таблицы. 1НФ: атомарность. 2НФ: полная зависимость. 3НФ: нет транзитивных зависимостей.
- **Нефункциональные требования (NFR)** — требования к свойствам системы: производительность, доступность, безопасность, масштабируемость и др.

## O
- **OLAP (Online Analytical Processing)** — аналитическая обработка данных. Колоночное хранение, денормализация, агрегации. Примеры: ClickHouse, BigQuery.
- **OLTP (Online Transaction Processing)** — транзакционная обработка в реальном времени. Нормализация, строковое хранение. Примеры: PostgreSQL, MySQL.
- **ORM (Object-Relational Mapping)** — технология сопоставления объектов приложения с таблицами БД. Примеры: SQLAlchemy, Hibernate.

## P
- **PACELC** — расширение CAP-теоремы (Дэниэл Абади, 2010): если есть разбиение сети (P), выбираем A или C; иначе (E) выбираем Latency или Consistency.
- **PII (Personally Identifiable Information)** — персональные данные, позволяющие идентифицировать человека: ФИО, email, телефон, ИНН, паспорт, биометрия.
- **PITR (Point-in-Time Recovery)** — восстановление базы данных до конкретной точки во времени с использованием полного бэкапа и WAL-архивов.
- **ПК (Промежуточная таблица)** — таблица для реализации связи M:N. Содержит составной ключ из двух внешних ключей.
- **Подготовленные выражения (Prepared Statements)** — механизм защиты от SQL-инъекций: СУБД компилирует план запроса до подстановки параметров.
- **Пул соединений (Connection Pool)** — набор предварительно созданных соединений с БД.

## R
- **Репликация** — процесс копирования данных с одного узла (Master/Primary) на другие (Replica/Secondary) для повышения доступности и распределения нагрузки.
- **RPO (Recovery Point Objective)** — максимально допустимый период потери данных при сбое. RPO = 0 означает нулевую потерю.
- **RTO (Recovery Time Objective)** — максимально допустимое время простоя системы после сбоя.
- **Репликация асинхронная** — Master не ждёт подтверждения реплики перед COMMIT. Низкая latency, риск потери данных.
- **Репликация синхронная** — Master ждёт подтверждения реплики перед COMMIT. Гарантия сохранности, высокая latency.
- **Resume-Driven Development** — антипаттерн: выбор технологии для изучения разработчиком, а не по потребности проекта.

## S
- **SLO (Service Level Objective)** — целевое значение метрики качества обслуживания (например, P95 latency < 200ms).
- **SLA (Service Level Agreement)** — соглашение об уровне обслуживания с юридическими последствиями.
- **Снапшот** — мгновенная копия состояния данных в определённый момент времени (LVM, ZFS, облачные).
- **Стейкхолдер** — заинтересованная сторона: заказчик, пользователи, разработчики, администраторы, регуляторы.
- **Split-Brain** — ситуация в распределённой системе, когда оба узла считают себя Master. Решение: Quorum (N/2 + 1).
- **Суррогатный ключ** — см. Ключ суррогатный.

## T
- **Транзакция** — логическая единица работы с БД: все операции выполняются или все откатываются.
- **Транзитивная зависимость** — функциональная зависимость X → Y → Z, нарушающая 3НФ.
- **TCO (Total Cost of Ownership)** — общая стоимость владения решением: лицензии, инфраструктура, поддержка, персонал.
- **Токенизация** — замена чувствительных данных на токен; оригинал хранится в защищённом хранилище (Vault).

## U
- **Ubiquitous Language** — в DDD: единый язык, используемый всеми участниками проекта (разработчики, аналитики, бизнес).

## W
- **WAL (Write-Ahead Log)** — журнал предзаписи: механизм обеспечения долговечности (Durability) транзакций. Изменения пишутся в журнал до применения к данным.
- **Write-Through** — паттерн кэширования: запись происходит одновременно в кэш и в БД.
- **Write-Behind (Write-Back)** — паттерн кэширования: запись в кэш, асинхронный сброс в БД. Быстрее, но риск потери.

## Z
- **Zero-Downtime миграция** — изменение схемы БД без остановки работы приложения. Паттерн: Expand and Contract.

## 1-9
- **152-ФЗ** — Федеральный закон РФ «О персональных данных». Требует согласия, локализации данных в РФ, уведомления Роскомнадзора.
- **1НФ** — Первая нормальная форма: атомарность атрибутов, нет повторяющихся групп, есть PK.
- **2НФ** — Вторая нормальная форма: 1НФ + все неключевые атрибуты полностью зависят от PK.
- **3НФ** — Третья нормальная форма: 2НФ + нет транзитивных зависимостей.
