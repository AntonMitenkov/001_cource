# Требования по BABOK: виды, SMART, MoSCoW

## Иерархия требований (BABOK Guide v3)
Бизнес-требования (зачем? какая цель?)
↓
Пользовательские требования (что пользователь хочет делать?)
↓
Функциональные требования (что система должна делать?)
↓
Нефункциональные требования (как система должна работать?)

### 1. Бизнес-требования
Высокоуровневые цели организации.
Пример: «Увеличить конверсию в покупку на 15% за 6 месяцев».

### 2. Пользовательские требования
Что пользователь хочет достичь с помощью системы.
Пример: «Покупатель хочет быстро найти товар по фото».

### 3. Функциональные требования (FR)
Конкретные функции системы.
Пример: «Система должна позволять загрузить изображение и показать похожие товары».

### 4. Нефункциональные требования (NFR)
Атрибуты качества и ограничения.
Пример: «Поиск по фото должен возвращать результат за < 2 секунд при нагрузке 100 RPS».

## SMART-требования

Каждое функциональное требование должно быть:

| Критерий | Описание | Пример нарушения |
|:---|:---|:---|
| **S**pecific | Конкретное, однозначное | «Система должна быть быстрой» ❌ |
| **M**easurable | Измеримое | «Отклик < 200мс на P95» ✅ |
| **A**chievable | Достижимое | Не требовать невозможного |
| **R**elevant | Релевантное бизнес-цели | Не «потому что хочется» |
| **T**ime-bound | С конкретными сроками | «К моменту запуска в Q2» |

## Нумерация требований

- Формат: FR-001, FR-002, ..., NFR-001, NFR-002, ...
- Позволяет ссылаться на требования в ADR и тестах
- Обеспечивает трассируемость: бизнес-цель → требование → реализация → тест

## Приоритизация MoSCoW

| Приоритет | Описание | Пример |
|:---|:---|:---|
| **Must** | Без этого система не может работать | Авторизация, оформление заказа |
| **Should** | Важно, но есть обходной путь | Фильтры по цене |
| **Could** | Желательно, но не критично | Рекомендации «похожие товары» |
| **Won't have** | Не в текущем релизе | Программа лояльности v2 |

## Типовые проблемы данных (для анализа)

| Проблема | Описание | Пример |
|:---|:---|:---|
| Дублирование | Одни данные хранятся в нескольких местах | Адрес клиента в 3 таблицах |
| Потеря данных | Данные теряются при сбоях или миграциях | Заказы без бэкапа |
| Рассинхронизация | Разные системы показывают разные данные | Остаток на сайте ≠ остаток на складе |
| Ручные операции | Данные переносятся вручную | Выгрузка из Excel в систему |
| Медленный поиск | Невозможно быстро найти нужные данные | Поиск по 10 млн записей без индексов |
