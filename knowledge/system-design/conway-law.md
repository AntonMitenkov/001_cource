# Закон Конвея

## Формулировка

«Организации, проектирующие системы, вынуждены создавать проекты, являющиеся копией структуры коммуникаций этой организации.»

Оригинал: "Any organization that designs a system will produce a design whose structure is a copy of the organization's communication structure."

Автор: Мелвин Конвей (Melvin E. Conway), 1968.

## Суть

- Архитектура системы отражает организационную структуру команды
- Если в компании 3 команды → вероятно 3 крупных компонента в системе
- Если команды не общаются между собой → между компонентами будут слабые интерфейсы или их отсутствие
- Изменение архитектуры без изменения структуры команды часто невозможно

## Примеры

| Организация | Архитектура |
|:---|:---|
| 1 команда «полного цикла» | Монолит |
| 3 команды: фронтенд, бэкенд, БД | Трёхслойная архитектура |
| 5 микросервисных команд | 5 микросервисов |
| 2 команды в разных часовых поясах | Асинхронная интеграция между их компонентами |

## Обратный закон Конвея (Inverse Conway Maneuver)

Если мы хотим получить определённую архитектуру, мы должны сначала выстроить структуру команд под неё.

Пример: хотим микросервисную архитектуру → формируем маленькие кросс-функциональные команды по продуктовым доменам.

## Связь с курсом

- Лекция 1: закон Конвея объясняет, почему архитектурные решения имеют организационные последствия
- Лекция 2: Bounded Contexts часто совпадают с границами команд
- Лекция 7: при финальной сборке учитываем, кто будет эксплуатировать систему

## Источник
