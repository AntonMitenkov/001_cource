# Event Storming

## Определение

Event Storming — метод совместного анализа бизнес-процессов, в котором участники (разработчики, аналитики, бизнес) совместно выкладывают на стене (или виртуальной доске) последовательность доменных событий.

Изобретён: Альберто Брандолини (Alberto Brandolini), 2013.

## Зачем нужен

- Выявить все бизнес-события и процессы
- Обнаружить скрытые зависимости и пробелы
- Определить границы Bounded Contexts
- Создать общий язык между бизнесом и разработкой (Ubiquitous Language)
- Выявить проблемные зоны до начала проектирования

## Цветовая кодировка стикеров

| Цвет | Элемент | Описание | Пример |
|:---|:---|:---|:---|
| 🟠 Оранжевый | Domain Event | Факт, который уже произошёл (в прошедшем времени) | «Заказ оформлен», «Платёж проведён» |
| 🔵 Синий | Command | Намерение пользователя или системы | «Оформить заказ», «Отменить платёж» |
| 🟡 Жёлтый | Aggregate | Сущность, над которой выполняется команда | «Заказ», «Платёж», «Клиент» |
| 🩷 Розовый | Hot Spot | Проблемная зона, неопределённость, вопрос | «Не понятно, кто отвечает за возврат» |
| 🟢 Зелёный | Read Model | Данные, которые нужно показать пользователю | «Экран списка заказов», «Детали платежа» |

## Процесс проведения

1. **Chaotic Exploration** — все участники свободно клеят оранжевые стикеры (события)
2. **Enforce Timeline** — выстроить события в хронологическом порядке (слева направо)
3. **Identify Commands** — добавить синие стикеры: что вызывает каждое событие
4. **Identify Aggregates** — добавить жёлтые стикеры: над чем выполняется команда
5. **Identify Problems** — отметить розовым: где есть неопределённость, конфликты, пробелы

## Связь с проектированием БД

| Элемент Event Storming | Артефакт БД |
|:---|:---|
| Доменное событие | Факт для хранения (таблица событий или записей) |
| Агрегат | Граница транзакции; будущая таблица или группа таблиц |
| Команда | API-эндпоинт или метод сервиса |
| Read Model | Представление (View) или запрос |
| Горячая зона | Требует дополнительного анализа или ADR |

## Пример для маркетплейса
[Оформить заказ] → (Заказ) → 🟠 Заказ создан
[Провести оплату] → (Платёж) → 🟠 Платёж проведён
[Подтвердить наличие] → (Склад) → 🟠 Товар зарезервирован
[Отправить заказ] → (Доставка) → 🟠 Заказ передан в доставку
🩷 Что если товар закончился после оплаты?

## Правила проведения

- Участвуют все: разработчики, аналитики, бизнес, поддержка
- Использовать простой язык, без технического жаргона
- Одно событие = один стикер
- События в прошедшем времени: «Заказ создан», а не «Создать заказ»
- Не критиковать идеи на этапе Chaotic Exploration
