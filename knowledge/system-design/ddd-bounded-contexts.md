# DDD: Bounded Contexts и предметная область

## Определение

Domain-Driven Design (DDD) — подход к проектированию программного обеспечения, в котором модель предметной области является центральным элементом.

Автор: Эрик Эванс (Eric Evans), 2003.

## Ключевые понятия

### Домен (Domain)
Сфера деятельности, для которой создаётся система.
Примеры: E-commerce, FinTech, HealthTech, IoT, образование.

### Субдомен (Subdomain)
Часть домена. Бывают:
- **Ключевой (Core)** — конкурентное преимущество (например, алгоритм рекомендаций)
- **Поддерживающий (Supporting)** — нужен, но не уникален (каталог товаров)
- **Общий (Generic)** — стандартные решения (аутентификация, оплата)

### Bounded Context (Ограниченный контекст)
Явная граница, внутри которой модель предметной области остаётся консистентной.

**Ключевой принцип:** одна бизнес-сущность может иметь разные модели в разных контекстах.

### Пример: сущность «Заказ» в разных контекстах

| Контекст | Что важно | Атрибуты |
|:---|:---|:---|
| Продажи | Статус, сумма, клиент | order_id, status, total, customer_id |
| Склад | Позиции, габариты, наличие | order_id, items[], weight, warehouse_id |
| Финансы | Налоги, скидки, валюты | order_id, tax_amount, discount, currency |
| Доставка | Адрес, трек, сроки | order_id, address, tracking_number, eta |

### Ubiquitous Language (Единый язык)
Все участники проекта (разработчики, аналитики, бизнес) используют одинаковые термины.
Термины фиксируются в глоссарии проекта.

### Связь между контекстами

Контексты взаимодействуют через:
- **API (синхронно)** — REST, gRPC
- **События (асинхронно)** — публикация доменных событий
- **Shared Kernel** — общая часть модели (использовать осторожно)
- **Anti-Corruption Layer** — адаптер для защиты от чужой модели

## Влияние домена на архитектуру данных

| Домен | Особенности данных | Приоритет |
|:---|:---|:---|
| FinTech | Строгая консистентность, аудит, регуляторика | ACID, Consistency |
| Social Media | Большие объёмы, скорость, допустима задержка | Eventual consistency, throughput |
| IoT | Огромные потоки записи, временные ряды | Write-heavy, time-series |
| E-commerce | Гибкая схема, поиск, каталог | Read-heavy, поиск |
| HealthTech | Конфиденциальность, регуляторика, интеграции | Security, compliance |
