# Нефункциональные требования (NFR)

## Определение

Нефункциональные требования (NFR, Non-Functional Requirements) описывают **как** система должна работать, а не **что** она должна делать.

NFR определяют атрибуты качества системы и ограничения на реализацию.

## Классификация NFR

### Производительность (Performance)
- **Latency** — время отклика одного запроса (например, P95 < 200ms)
- **Throughput** — количество запросов в единицу времени (например, 1000 RPS)
- **Время отклика** — общее время обработки пользовательского действия

### Масштабируемость (Scalability)
- **Вертикальная (Scale Up)** — увеличение ресурсов одного сервера (CPU, RAM, диск)
- **Горизонтальная (Scale Out)** — добавление серверов в кластер
- Пределы масштабирования и стоимость каждого подхода

### Доступность (Availability)
- Процент времени, когда система работает корректно
- Примеры:
  - 99% ≈ 3.65 дня простоя в год
  - 99.9% ≈ 8.7 часов простоя в год
  - 99.99% ≈ 52.6 минуты простоя в год
  - 99.999% ≈ 5.26 минуты простоя в год
- Метрики: SLA, SLO, SLI

### Надёжность (Reliability)
- Вероятность безошибочной работы в течение заданного времени
- Среднее время между сбоями (MTBF)
- Среднее время восстановления (MTTR)

### Безопасность (Security)
- **CIA Triad**: Confidentiality (конфиденциальность), Integrity (целостность), Availability (доступность)
- Аутентификация, авторизация, шифрование
- Защита от уязвимостей (SQL-инъекции, XSS, CSRF)
- Соответствие регуляторам (GDPR, 152-ФЗ, HIPAA)

### Сопровождаемость (Maintainability)
- Лёгкость внесения изменений
- Читаемость кода и документации
- Модульность и слабая связность

### Стоимость владения (TCO)
- Лицензии, инфраструктура, персонал
- Стоимость масштабирования
- Стоимость миграции при смене технологии

## Ограничения

Ограничения — это жёсткие рамки, которые нельзя нарушать:

### Бизнес-ограничения
- Бюджет
- Дедлайны
- Регуляторные требования (152-ФЗ, GDPR)
- Квалификация команды

### Технические ограничения
- Существующий стек технологий
- Инфраструктура (on-premise vs cloud)
- Совместимость с легаси-системами

## Метрики успеха (SLO/SLA)

| Метрика | Пример |
|:---|:---|
| P95 latency | < 200ms |
| Availability | 99.9% |
| Error rate | < 0.1% |
| RPO | < 1 час |
| RTO | < 30 минут |
