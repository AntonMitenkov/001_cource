# Реестр потенциальных конфликтов терминологии между лекциями

> Служебный файл этапа F1 (см. `tasks/WORK_PLAN.md`, п. 0.5). Фиксирует термины, которые используются в нескольких лекциях с разными акцентами или значениями. Задача редактора: сверить формулировки с `knowledge/glossary.md` и при необходимости унифицировать дефиниции либо явно развести значения в самом глоссарии.
> Составлено 14.10.2026 по фактическому содержанию final.md Л1–Л8.

## 1. Денормализация (Л3 ↔ Л8)

| | Лекция 3 | Лекция 8 |
|---|---|---|
| Акцент | Осознанное нарушение НФ на уровне **логической модели**: снимок цены, сводные таблицы; обязательный ADR | Денормализация как часть **стратегии масштабирования чтения**: материализованные проекции, OLAP-витрины |
| Потенциальный конфликт | Студент может вынести «денормализация = оптимизация производительности» уже с Л3, хотя там критерий — целостность фактов и бизнес-семантика | |
| Разрешение | В Л3 подчёркивать: мотив — фиксация факта (иммутабельный снимок), а не скорость; скорость появляется как мотив только в Л8 | Проверить формулировку в glossary.md: единая дефиниция + две области применения |

## 2. OLAP / DWH (Л4 ↔ Л8)

| | Лекция 4 | Лекция 8 |
|---|---|---|
| Акцент | OLAP как **класс нагрузки и класс СУБД** (колоночные движки) в матрице выбора; разделение OLTP/OLAP защищает SLO | OLAP как **конвейер**: ETL/ELT, витрины, кубы; сравнение на числах сканов |
| Потенциальный конфликт | Термин «OLAP» в Л4 означает «нагрузка», в Л8 — «система аналитики (DWH)». Возможное смешение «OLAP = конкретная технология» | |
| Разрешение | Ввести в глоссарии два сенса: OLAP (тип нагрузки) и DWH/OLAP-система (реализация); в Л4 ссылаться на первый, в Л8 — на второй |

## 3. SLA / SLO / SLI (Л1 ↔ Л6 ↔ Л7)

| | Где используется | Акцент |
|---|---|---|
| SLA | Л1 (критерии), Л6 (последствия простоев) | Внешнее обязательство перед клиентом с штрафами |
| SLO | Л1, Л6, Л7 (чек-лист отчёта) | Внутренняя цель надёжности |
| SLI | Л6 (метрики восстановления) | Измеряемый индикатор |
| Потенциальный конфликт | В художественных местах лекций SLA/SLO употребляются как синонимы («SLA-убийца» в Л4) | Разрешение: при первом употреблении в каждой лекции — явная скобка-раскрытие; проверить все вхождения grep'ом |

## 4. Consistency — три разных смысла (Л3 ↔ Л4 ↔ Л6)

| Сенс | Лекция | Определение |
|---|---|---|
| C в ACID | Л4 (транзакции) | Данные в конце транзакции удовлетворяют ограничениям схемы |
| C в CAP | Л4 (PACELC), Л6 (репликация) | Linearizability: все узлы видят одну историю записей |
| Нормализационная согласованность | Л3 | Один факт — одно место хранения (отсутствие аномалий обновления) |
| Потенциальный конфликт | Фраза «согласованность данных» без уточнения сенса встречается в Л3, Л4, Л6 | Разрешение: в глоссарии — три отдельные статьи; в текстах лекций при слове «согласованность» обязателен квалификатор (ACID/CAP/схема) |

## 5. Кэш vs Connection pool (Л5 ↔ Л8)

| | Лекция 5 | Лекция 8 |
|---|---|---|
| Объект | Пул **соединений** — переиспользование дорогих TCP/аутентификационных сессий к СУБД | Кэш **результатов/данных** — переиспользование ответов поверх хранилища |
| Потенциальный конфликт | Оба — «пул чего-то в памяти для ускорения»; студент может перенести протокол инвалидации кэша на пул соединений | Разрешение: в Л5 явно одним предложением развести: «пул держит соединения, не данные; инвалидировать здесь нечего» |

## 6. Projection / проекция (Л3 ↔ Л7 ↔ Л8)

| Сенс | Лекция |
|---|---|
| Проекция как реляционная алгебра / «view» контекста | Л3 (логическая модель) |
| Проекция в Event Sourcing — состояние, собранные из событий, с лагом | Л7 (CQRS/ES) |
| Материализованная проекция / витрина как объект масштабирования | Л8 |
| Потенциальный конфликт | Слово «проекция» в Л7 вводит новое значение после Л3 | Разрешение: в глоссарии — омонимия с двумя статьями; в Л7 при первом употреблении дать определение заново |

## 7. Шард vs Партиция (Л7 ↔ Л8)

| | Термин | Граница |
|---|---|---|
| Л7 | Шардирование — распределение данных по **нескольким серверам** (shared-nothing) | архитектурный уровень |
| Л8 | Партиционирование — деление таблицы внутри **одной СУБД**; ступень перед шардированием в «лестнице» | физический уровень |
| Потенциальный конфликт | В обиходе «шард» и «партиция» синонимичны; в курсе это разные ступени лестницы масштабирования | Разрешение: убедиться, что в Л8 лестница явно противопоставляет партиционирование шардированию; в глоссарии — взаимные ссылки |
