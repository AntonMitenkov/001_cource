# Три уровня моделей данных

## Обзор

Проектирование данных проходит через три уровня абстракции:

| Уровень | Аудитория | Зависимость от СУБД | Детализация |
|:---|:---|:---|:---|
| Концептуальная | Бизнес, стейкхолдеры | Нет | Сущности и связи, без типов данных |
| Логическая | Архитекторы, аналитики | Нет (независима) | Таблицы, колонки, ключи, связи |
| Физическая | Разработчики, DBA | Да (конкретная СУБД) | Типы данных, индексы, партиции |

## Концептуальная модель

**Цель:** описать бизнес-сущности и их связи без технических деталей.

**Элементы:**
- Сущность (Entity) — объект предметной области (Клиент, Заказ, Товар)
- Атрибут (Attribute) — свойство сущности (имя, цена, дата)
- Идентификатор — атрибут, однозначно определяющий сущность
- Связь (Relationship) — отношение между сущностями
- Кардинальность — тип связи: 1:1, 1:N, M:N
- Обязательность — связь обязательна или опциональна

**Бизнес-правила:**
- «Заказ не может быть оформлен без клиента»
- «Один товар может входить в несколько заказов»
- «У клиента может не быть заказов (новый клиент)»

## Логическая модель

**Цель:** описать структуру данных независимо от конкретной СУБД.

**Элементы:**
- Таблица (сущность → таблица)
- Колонка (атрибут → колонка)
- Тип данных (общий: целое, строка, дата, булево)
- Первичный ключ (PK)
- Внешний ключ (FK)
- Ограничения (NOT NULL, UNIQUE, CHECK)
- Связи: 1:1, 1:N, M:N (через промежуточную таблицу)

**Не содержит:**
- Конкретных типов данных СУБД (VARCHAR(255) vs TEXT)
- Индексов
- Партиций
- Хранимых процедур

## Физическая модель

**Цель:** описать реализацию в конкретной СУБД.

**Содержит:**
- Конкретные типы данных (PostgreSQL: SERIAL, VARCHAR(255), JSONB, UUID)
- Индексы (B-Tree, GIN, GiST)
- Партиционирование
- Табличные пространства
- Последовательности (sequences)
- Триггеры и хранимые процедуры

### Физическая (PostgreSQL):
```sql
CREATE TABLE client (
    client_id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL
);

CREATE TABLE "order" (
    order_id SERIAL PRIMARY KEY,
    client_id INTEGER NOT NULL REFERENCES client(client_id),
    order_date TIMESTAMP DEFAULT NOW(),
    status VARCHAR(50) CHECK (status IN ('new', 'paid', 'shipped', 'cancelled'))
);
