# Ключи и ограничения (Constraints)

## Первичный ключ (Primary Key, PK)

- Уникально идентифицирует каждую строку в таблице
- Не может быть NULL
- Один на таблицу
- Индексируется автоматически
- Не должен меняться (по возможности)

## Внешний ключ (Foreign Key, FK)

- Ссылается на первичный ключ другой таблицы
- Обеспечивает ссылочную целостность
- Может быть NULL (опциональная связь)
- Может повторяться (связь 1:N)
- Действия при удалении/обновлении: CASCADE, SET NULL, RESTRICT, NO ACTION

## Типы ключей

### Естественный ключ
Имеет бизнес-смысл.
Примеры: email, ИНН, ISBN, номер паспорта.

| Плюсы | Минусы |
|:---|:---|
| Понятен без дополнительной таблицы | Может измениться (смена фамилии, перерегистрация) |
| Уникален по бизнес-логике | Может быть длинным (составные) |
| Не требует генерации | Может содержать специальные символы |

### Суррогатный ключ
Искусственно сгенерирован.
Примеры: SERIAL (автоинкремент), UUID, ULID.

| Плюсы | Минусы |
|:---|:---|
| Неизменен | Не несёт бизнес-смысла |
| Компактен (для SERIAL) | Требует генерации |
| Удобен для связей | Может требовать дополнительной логики |

**Рекомендация:** использовать суррогатные ключи как PK, естественные — как UNIQUE.

### Составной ключ
Состоит из нескольких колонок.
Используется в промежуточных таблицах для связи M:N.

Таблица: ПозицияЗаказа
PK: (order_id, product_id)
FK: order_id → Заказ
FK: product_id → Товар



## Ограничения (Constraints)

| Ограничение | Назначение | Пример |
|:---|:---|:---|
| `NOT NULL` | Запрещает пустые значения | `name VARCHAR NOT NULL` |
| `UNIQUE` | Уникальность значения | `email VARCHAR UNIQUE` |
| `CHECK` | Условие на значение | `price CHECK (price > 0)` |
| `PRIMARY KEY` | = UNIQUE + NOT NULL | `id SERIAL PRIMARY KEY` |
| `FOREIGN KEY` | Ссылочная целостность | `client_id REFERENCES client(id)` |
| `DEFAULT` | Значение по умолчанию | `created_at TIMESTAMP DEFAULT NOW()` |
