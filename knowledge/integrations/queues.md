# Очереди: базовые понятия

## Что такое очередь

Очередь — структура данных и инфраструктурный примитив, обеспечивающий
упорядоченную (как правило FIFO) передачу единиц работы от производителя
к потребителю с возможностью временного хранения.

Ключевые свойства:
- Асинхронность: отправитель и получатель не обязаны существовать
  одновременно.
- Буферизация: очередь сглаживает пиковые нагрузки.
- Развязка во времени: сообщение может быть обработано позже.

## Task Queue

Очередь заданий, ориентированная на выполнение единиц работы
(задач) воркерами.

Характеристики:
- Одна задача обычно обрабатывается одним воркером (конкурирующие
  потребители).
- Акцент на выполнении действия, а не на передаче данных.
- Типичные сценарии: отправка e-mail, генерация отчётов,
  обработка изображений, вызовы внешних API.

Примеры: Celery + Redis/RabbitMQ, Sidekiq (Ruby), BullMQ (Node.js).

## Message Queue

Очередь сообщений, ориентированная на надёжную доставку данных между
компонентами системы.

Характеристики:
- Сообщение несёт бизнес-смысл (событие, команду, запрос).
- Акцент на гарантиях доставки, порядке, durability.
- Может поддерживать маршрутизацию, фильтрацию, приоритеты.

Примеры: RabbitMQ, ActiveMQ, Amazon SQS, Azure Queue Storage.

## Когда использовать очереди

- Нужно развязать производителя и потребителя во времени.
- Требуется сгладить всплеск нагрузки (буферизация).
- Обработка может выполняться асинхронно и не блокировать основной поток.
- Необходима балансировка между несколькими воркерами.
- Допустима eventual consistency между подсистемами.
- Повторная обработка при сбоях критична.

## Чем очередь НЕ является

- **Не система хранения.** Очередь не предназначена для произвольных
  запросов по данным, индексирования или сложных выборок.
- **Не база данных.** Нет транзакций над множеством записей, нет
  реляционной модели, нет полнотекстового поиска.
- **Не кэш.** Данные в очереди конечное число раз читаются и удаляются.
- **Не event log.** Классическая очередь не рассчитана на долгосрочное
  хранение и replay истории.

## Очередь ≠ База данных

| Аспект | Очередь | База данных |
|---|---|---|
| Жизненный цикл записи | Временный: прочитал → удалил | Долгосрочный |
| Модель доступа | FIFO / конкурентный dequeue | Произвольные запросы |
| Индексация | Отсутствует или минимальна | Полноценная |
| Транзакционность | На уровне сообщения | ACID на уровне записей/таблиц |
| Объём хранения | Ограничен, рассчитан на буфер | Практически не ограничен |
| Назначение | Передача работы/данных | Хранение и извлечение данных |

Попытка использовать очередь как БД приводит к потере данных,
невозможности аудита и деградации производительности при росте
глубины.
