# Результаты обучения (Learning Outcomes)

## 1. System Design
- Студент умеет переводить бизнес-цели в архитектурные драйверы и требования.
- Студент умеет рисовать диаграммы C4 System Context и Container Diagram для визуализации архитектуры.
- Студент понимает влияние бизнес-контекста на выбор архитектурных паттернов.
- Студент умеет декомпозировать сложную систему на логические компоненты.
- Студент умеет готовить итоговый Architecture Blueprint системы.
- Студент понимает роль архитектора в процессе разработки и принятия решений.

## 2. Domain and Requirements
- Студент умеет выявлять границы предметной области (Bounded Contexts).
- Студент умеет строить Domain Context Map для отображения взаимосвязей между доменами.
- Студент владеет техниками Event Storming для анализа бизнес-процессов.
- Студент умеет формулировать Quality Attribute Scenarios (сценарии атрибутов качества).
- Студент понимает разницу между функциональными и нефункциональными требованиями.
- Студент умеет выделять ключевые сущности и агрегаты в предметной области.

## 3. Databases
- Студент умеет выбирать класс СУБД (реляционная, документная, key-value, колоночная, графовая) под конкретную задачу.
- Студент понимает различия между OLTP и OLAP системами и их назначение.
- Студент знает основные принципы ACID и BASE и области их применения.
- Студент умеет обосновать выбор типа хранилища через trade-offs.
- Студент понимает концепции шардирования, репликации и консистентности.
- Студент готов к углубленному изучению SQL и администрирования в курсе "Базы данных".

## 4. Integrations and Queues
- Студент умеет отличать очередь сообщений от базы данных и не использовать одну вместо другой нецелевым образом.
- Студент понимает разницу между очередями (Queues) и брокерами сообщений (Brokers).
- Студент умеет проектировать механизмы retry (повторных попыток) для обработки временных сбоев.
- Студент умеет проектировать Dead Letter Queues (DLQ) для обработки неуспешных сообщений.
- Студент понимает важность идемпотентности при обработке событий и сообщений.
- Студент знаком с паттернами Outbox/Inbox и Event Streaming.

## 5. Quality Attributes
- Студент умеет анализировать требования к масштабируемости системы (горизонтальное/вертикальное).
- Студент умеет проектировать решения с учетом требований к надежности (Reliability) и доступности (Availability).
- Студент понимает принципы безопасности данных на архитектурном уровне.
- Студент умеет оценивать производительность системы и узкие места.
- Студент знает методы обеспечения отказоустойчивости распределенных систем.
- Студент умеет балансировать между различными атрибутами качества.

## 6. Decision Making
- Студент умеет проводить анализ компромиссов (trade-offs) при выборе технологий и архитектурных стилей.
- Студент понимает концепцию TCO (Total Cost of Ownership) и учитывает её при выборе решений.
- Студент знаком с методом ATAM для оценки архитектуры.
- Студент умеет писать Architectural Decision Records (ADR) для фиксации принятых решений.
- Студент умеет аргументировать выбор технологии бизнес-выгодами и ограничениями.
- Студент понимает экономические последствия архитектурных решений.

## 7. Communication and Architecture Documentation
- Студент умеет создавать понятную архитектурную документацию для разных стейкхолдеров.
- Студент владеет навыками презентации архитектурных решений технической и бизнес-аудитории.
- Студент умеет использовать стандартные нотации и шаблоны для описания архитектуры.
- Студент понимает важность версионирования архитектурной документации.
- Студент умеет вести глоссарий проекта для устранения терминологических разночтений.
- Студент умеет собирать и структурировать обратную связь по архитектурным решениям.
