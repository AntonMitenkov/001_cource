Тема: «System Design: финальная сборка, Peer-Review и защита отчета».

Краткая цель: интегрировать все компоненты в единую архитектурную схему, провести взаимное рецензирование и подготовиться к защите проекта.

### Обязательные концепции:
- компоненты System Design: Primary Storage, Cache, Queues, Analytics;
- архитектурные паттерны: CQRS, Event Sourcing, шардирование;
- фиксация компромиссов (ADR) и финальная проверка отчёта (чек-лист);
- Peer-Review: правила конструктивной обратной связи и рубрики оценки;
- структура и критерии успешной защиты архитектурного проекта.

### Практика:
собрать итоговый Architecture Blueprint учебного кейса; провести Peer-Review по рубрике; подготовить защиту.

### Acceptance criteria:
- студент собирает компоненты архитектуры (storage, cache, queues, analytics) в единую схему;
- студент объясняет CQRS / Event Sourcing / шардирование через trade-offs и контекст применения;
- студент проводит конструктивный Peer-Review по рубрике;
- студент защищает решение перед технической и бизнес-аудиторией, опираясь на ADR и NFR.

### Связь с лекциями:
- предыдущая: объединяет решения по хранению и надёжности (Лекции 4–6) в единую систему;
- следующая: добавляет стратегии масштабирования и аналитики для растущих систем (Лекция 8).
