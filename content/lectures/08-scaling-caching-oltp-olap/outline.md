# Outline — Лекция 8: Масштабирование: производительность, кэширование и аналитика (OLTP vs OLAP)

**Дата:** 12.10.2026 · **Этап:** outline · **Тайминг:** 80 мин (lesson-contract) · **База:** brief.md + lesson-08.spec.md

## Цель занятия
Освоить паттерны масштабирования работающей системы: горячие/холодные данные, кэширование с инвалидацией, компромиссы индексирования, разделение OLTP/OLAP через DWH; оформить результат как секцию «Стратегия масштабирования» итогового Blueprint.

## Learning objectives (по acceptance criteria spec)
К концу занятия студент способен (уровень WHAT/WHY):
1. **LO1.** Классифицировать данные как горячие/тёплые/холодные и обосновать для каждого класса носитель, репликацию и retention-стратегию. *(AC: классификация hot/cold)*
2. **LO2.** Выбрать стратегию кэширования (Cache-Aside / Read-Through / Write-Through / Write-Behind) для заданного контекста и описать проблему инвалидации через trade-offs (freshness ↔ latency ↔ сложность). *(AC: стратегия + инвалидация)*
3. **LO3.** Объяснить принцип B-Tree-индекса и сформулировать компромисс «скорость чтения vs стоимость записи/хранения»; составить топ запросов с обоснованием индексов. *(AC: компромиссы индексирования)*
4. **LO4.** Разделить OLTP- и OLAP-нагрузки и обосновать вынос аналитики в хранилище/колоночную БД. *(AC: разделение OLTP/OLAP)*
5. **LO5.** Описать базовый ETL/ELT-поток (источник → извлечение → загрузка → модель → дашборд) для аналитики без нагрузки на прод. *(AC: ETL/ELT)*
6. **LO6.** Критически разобрать публичные архитектуры (кейсы Netflix/Uber) на предмет применимости перенятых паттернов в своём контексте (NFR, бюджет, команда, масштаб). *(Case Studies из spec)*
